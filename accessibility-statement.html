Accessibility Statement

Every Indie Game Deserves to Be Seen — and every player deserves equal access to find them.

Last updated: October 2026 · Contact: services@digitalinfohub.net

Our commitment

PixelFair aims to meet the Web Content Accessibility Guidelines (WCAG) 2.1 Level AA and the requirements of the UK Equality Act 2010 as they apply to websites. Accessibility is treated as a launch requirement, not an afterthought.

Accessibility features already implemented

  • Semantic structure: landmarks (header/nav/main/footer), one h1 per page, logical heading order.
  • Keyboard navigation: all interactive elements reachable; visible amber focus outlines; skip-to-content link on every page; Escape closes the mobile menu.
  • Forms: every input has a programmatic label; required fields marked with aria-required; validation errors announced via role="alert"/aria-live; errors move focus to the first invalid field.
  • Colour contrast: body text targets at least 4.5:1 against navy backgrounds; gradient buttons use dark text for contrast.
  • Motion: full prefers-reduced-motion support disables animations, transitions and smooth scrolling automatically.
  • Media: descriptive alt/aria-label text for artwork placeholders; decorative glyphs hidden from screen readers.
  • Responsive design: usable from 320px phones to large desktops without horizontal scrolling or clipped content.
  • Language: pages declare lang="en"; status messages use polite live regions.

Known limitations (documented honestly)

  • Game detail pages are dynamic (query-parameter driven); deep-linking to a specific game from assistive tech works, but shareable pretty URLs are Coming Soon.
  • Emoji-based placeholder artwork may be read inconsistently across screen readers until real images with curated alt text replace them (Coming Soon).
  • No formal third-party WCAG audit has been completed yet; self-assessment only.

Accessibility feedback & complaints

If you hit an accessibility barrier, email services@digitalinfohub.net describing the page, your device/browser/assistive technology and what went wrong. We welcome reports and prioritise fixes that block access to core content. A formal dispute-resolution process aligned to UK regulations will be published when the service scales (Coming Soon).

Technologies relied upon

HTML5, CSS (embedded per page), vanilla JavaScript, browser-native mailto handling. No third-party widgets are currently loaded, which removes many common accessibility risks.

Date of statement

This statement was last reviewed in October 2026 and is revisited whenever significant features ship.
